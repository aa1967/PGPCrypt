# PGPCrypt 0.1.0 alpha11

Debian 13 amd64 evaluation package.

- Ordinary session status for dummy opens; backend write restrictions remain.
- Conversion explains that BOTH age v1 and KDBX 4.1 destinations omit the
  source's per-vault dummy/emergency/inactivity protection companion records.
- Key context menus provide public-key/fingerprint/value copying and existing
  management actions. Tables have cleaner defaults and remain sortable and
  resizable.
- Verify presents an explicit PASS/FAIL comparison of the verified signer and
  stored certificate, alongside the existing output. Failure returns no
  verified plaintext or trusted signer metadata.
- A terminal-style activity panel shows bounded, fixed, severity-colored events
  in memory only; it excludes credentials, content, paths, identities and
  advanced-protection activity.
- Identity overview lists all profiles and their key/document connections,
  with editable details alongside. New identity creation can assign available
  keys immediately.
- KDBX identities use actual KeePass groups, document entries and references to
  one canonical copy of each key. Legacy layouts remain readable.
- Notepad opens in a separate window by default, configurable in Vault settings.
  Embedded and separate layouts share one editor and worker session; lock closes
  the session windows.

Age writes schema 7; KDBX settings write schema 6. Older app versions reject
new snapshots. Keep backups before upgrading. This remains alpha software with
an experimental upstream KDBX writer and no independent security audit.

A hidden-storage investigation compares age/KDBX constraints with VeraCrypt.
No root helper, cosmetic sidecar hiding or writable dummy was added; ordinary
status text does not establish plausible deniability. Read
`docs/HIDDEN_STORAGE_RESEARCH.md` for feasibility and remaining work.

Post-push validation passed: all 72 Rust checks across final combined runs;
independent age schema 1–7, GnuPG and KeePassXC group interoperability; packaged
Qt workflows for both formats, shared-window transitions, verification failure
recovery, neutral dummy status, activity bounds and lock cleanup. No system
installation or real Qubes transport was exercised. See `docs/VALIDATION.md`.
