# PGPCrypt 0.1.0 alpha16

Debian 13 amd64. Source branch: `pgpcrypt-alpha16`.

The landing page now offers an optional LUKS utility along its bottom edge:
unlock and mount existing LUKS drives or file containers, create a new LUKS2/ext4
container, and explicitly unmount/lock volumes. Ordinary age/KDBX create/open
flows and the database password page remain available without LUKS.

The GUI uses Debian's UDisks/cryptsetup service with existing polkit
authorization. It never runs as root, installs no privileged project helper,
and only formats newly created private files. Existing files/drives cannot be
formatting targets. Creation fully allocates the chosen capacity with system
randomness on a background thread and can be stopped before formatting; partial
files are left for manual inspection/removal. Mount requests use
`nosuid,nodev,noexec` with an optional read-only mode. Busy unmounts fail without
forcing close or claiming the volume was locked.

**Database lock and LUKS lock are separate.** Volumes can remain mounted after
locking a database, closing PGPCrypt or crashing. Use **Unmount & lock**, close
other programs using the volume, and confirm completion. Operating-system
access, LUKS headers, backups, snapshots and previously captured copies remain
outside any invisibility/erasure promise. This does not add real/decoy/wipe
behavior to LUKS keyslots.

Question-mark controls provide hover/click/keyboard explanations for LUKS and
selected password/security settings. Current errors, memory state and destructive
confirmation warnings remain visible.

The package adds UDisks2, its crypto plugin, cryptsetup-bin, ext4 utilities and
polkit dependencies, with a recommended desktop authentication agent. Qubes
users install these in the vault guest, never dom0. More details: `docs/LUKS.md`.

`docs/KDBX_MULTI_KEYSLOT_REVIEW.md` evaluates the supplied four-format proposal,
recommends corrected base-plus-suffix attachment routing for the requested UX,
and documents interoperability, entropy, wire-layout, expiry and wipe/history
issues. **No new KDBX multi-keyslot or writable decoy format is implemented in
this release.** Existing age/KDBX encryption and protection behavior is unchanged.

Validation results are recorded in `docs/VALIDATION_ALPHA16.md`. Real kernel
mounts, polkit prompts and native Qubes hardware integration require target-
system validation; isolated service tests do not establish those outcomes.
